Software Recommendations?

I recommend getting Visual Studio Code if you don't have it installed yet. Install it, and open your s&box game project solution (.slnx file) - you will be recommended to install two extensions, one of them is Slang, it will provide you a nearly complete intellisense support for s&box shaders.

Slang will automatically add all necessary coding features like autocomplete, source references, and bunch of other useful little things. If you hover on variables or functions, it will tell you which file implements them. This is the best (and only) option at the moment.

References

If you plan to continue learning shaders on your own, you must know where you can find references for s&box shaders. My recommendation is to look up the source code. A huge portion of s&box shaders and backend is open source. Read it, try to understand it, mess around and try making changes to it, be curious.

  • s&box shaders location: Steam/steamapps/common/sbox/core/shaders (GitHub)

    Your engine comes with a huge pile of open source shaders, with varying purposes and effects.
  • s&box Documentation on shaders. This documentation covers lots of s&box shader API, helper functions and other useful things.
  • Microsoft also provides a complete documentation for nearly everything that HLSL has. This probably won't be very useful for you as a beginner, but once you figure out the basics I recommend visiting it for any specific things.
I really encourage you to read source code for s&box shaders located in core shaders, this may help you in figuring out some confusing parts about shaders. Do not hesitate to mess with your code: try changing values, math, functions and see what happens. Don't forget that you can visualize on screen nearly all data as colors. Don't be afraid to break shit, it's important to understand how data is represented in shaders and what every function does.

FXC Backend

This may be useful only for advanced users. As you may know, C# side of s&box is open source, and that includes a huge portion of shader backend. FXC files are the same HLSL/shader files. Most of them serve their purpose as shader backend. System, basic macros, helper functions, standard shading model, constant buffers, and lots of other things that you may ocassionally find in default shaders.

If you notice some magic function, or random variable with a spooky name, then it is probably coming from these FXC files! You can check out the source code here on GitHub.

This backend is not complete. There are some files that are not included in the open source repository, since most of these FXC files were written by Valve during HLVR (Half-Life Alyx) development.

The default lighting model that s&box uses relies on PBR, aka Physically Based Rendering. This means that you should probably be familiar with the default artist's PBR workflow; understanding why you would need texture maps such as albedo, roughness, normals, metalness, et cetera. This article on PBR by Marmoset staff seems to be pretty useful about the purpose of PBR and its texture maps. If you'd like to get extremely nerdy about it and understand the math behind it, "PBR Book" should be very helpful to you.

And another tip: take your time. If something isn't clicking in your head and you can't figure out some concept, try again later. Learning new things can fuck with your sanity sometimes, and sometimes the best solution is just "get some rest and come back to this later".

Do I need to understand programming?

Yeah. HLSL isn't a good language to start your programming adventures. If you have some experience with C#, you should feel comfortable with 99% of HLSL syntax. Just like most other languages, it is made of variables, classes, functions and statements. You can define custom functions and classes, and do any sorts of math.

If you're an artist looking to learn shaders and you have no programming experience, I highly recommend you to mess around with C# first and then come back to this later. It is possible to learn HLSL without prior knowledge, but I imagine that it will be quite painful... but I am not going to stop you.
